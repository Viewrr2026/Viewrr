# Media preview repairs

Feed YouTube/Vimeo players are permitted by the frame policy and receive an origin referrer. Vimeo unlisted hashes are preserved when creating embeds.

The multipart parser accepts an exact negotiated 8 MiB part and rejects the first excess byte. Per-part length verification and the 5 GiB total file limit remain enforced. The regression sends actual multipart requests through Express/Multer, including two full chunks and a small final chunk.

Uploaded project previews resolve through authenticated media access and stream in the web player, with contain fit, loading feedback and retry. Originals remain subject to server-verified payment. Existing app playback stays in the in-app viewer.

Hosted final links can have a separate uploaded preview. Freelancers can upload a preview while composing a delivery or choose Add preview for an existing delivery. Ownership, project, scope, readiness and the original reference are checked server-side. The preview is generated by the existing media worker with a watermark. Existing hosted deliveries without an uploaded copy require the freelancer to supply that copy; provider-hosted files are not downloaded automatically. Missing previews show a clear message and never fall back to an unpaid original.

## Rollout

1. Apply `migrations/0019_delivery_previews.sql` before deploying the new server. It adds one nullable column and can be run more than once. Existing rows are preserved.
2. Deploy the server/web changes on Render. No additional environment variables or storage keys are required.
3. Include the mobile changes in the planned 0.1.2 TestFlight build.
4. Check a public YouTube link and public/unlisted Vimeo links in Safari and on iPhone. Provider restrictions still apply.
5. Test a large feed upload, post it, and confirm playback. Automated tests cover real 8 MiB parts and 5 GiB metadata/part counts; a live 5 GiB transfer remains a deployment check.
6. As the freelancer, attach a preview to an existing hosted delivery. As the unpaid client, review the watermarked copy; verify the original remains locked. Verify final access after confirmed payment and preview retry after an expired playback URL.
