## Deployment and TestFlight handoff

Production follows `main` with automatic deployments. Publish the combined release
as one main update, then inspect the resulting deployment and application logs.
Confirm an actual image/video upload and watermarked preview against the production
bucket; a Live deployment alone does not establish storage or FFmpeg success.

From a clean checkout of the final main commit, in `mobile/`:

```bash
npm ci
npm run release:preflight
APP_ENV=production npx eas-cli@latest build --platform ios --profile production --auto-submit
```

The production profile uses `uk.co.viewrr.app`, the existing Expo project,
App Store Connect app `6816854034`, and `https://www.viewrr.co.uk`. Build numbers
increment remotely. The preview profile is ad hoc staging distribution and does
not upload to this TestFlight app. No cloud build has been started from this
workspace because EAS requires an authenticated Expo session.

The signed binary still needs iPhone testing: Photos/Files permissions and
cancellation, feed/profile/portfolio/showreel uploads, one-off deliveries, both
retainer workflows, preview playback and protected downloads. Retainer billing,
agreement changes and client approvals, and agency editing remain web workflows.
The existing privacy/reviewer-information checks remain required before public
App Store review. Uploading to TestFlight is not a public App Store release.

This is a new native binary, not an OTA update. Do not publish native-incompatible
JavaScript to existing binaries sharing the current app-version runtime.
